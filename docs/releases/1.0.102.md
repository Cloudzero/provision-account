# [1.0.102](https://github.com/Cloudzero/provision-account/compare/1.0.101...1.0.102) (2026-06-16)

> Flatten the connected stack to a single nested stack, move CUR creation to native CloudFormation, remove the deprecated audit / cloudtrail-owner connection types, adopt billing/resource/connection terminology, and provision a single fixed-name connection role

## Breaking / Behavioral Changes

### Single fixed-name connection role → requires `CAPABILITY_NAMED_IAM`
* Instead of separate resource-owner and master-payer roles, the stack now creates **one**
  cross-account role named **`cloudzero-connection`** (path `/cloudzero/`) for every connection;
  a billing connection layers CUR-bucket read access on top. Because the role has a fixed name,
  **the stack must be launched with the `CAPABILITY_NAMED_IAM` capability acknowledged.**
* The reactor payload is unchanged: the one role ARN is reported into both the `resource_owner`
  and `master_payer` link slots (and `legacy`), per the fixed contract.

### Terminology: billing / resource / connection
* Internal naming now uses **billing** (was "master payer"), **resource** (was "resource owner"),
  and **connection** (the CloudZero "account" concept). This is internal only — CloudFormation
  logical IDs, parameters, outputs, IAM policy names, and docs. The **reactor payload keys are
  unchanged** (`master_payer`, `resource_owner`, `is_master_payer_account`, …), as are AWS account
  identifiers and the `connected_account.yaml` launch filename.

### Billing-connection CUR creation now requires `us-east-1`
* The Cost and Usage Report for a billing connection is now created with the native
  **`AWS::CUR::ReportDefinition`** resource (plus `AWS::S3::Bucket` + `AWS::S3::BucketPolicy`),
  replacing the inline `Custom::CostAndUsageReport` Lambda. AWS only supports this resource in
  `us-east-1`, so **billing connections that need a new CUR must be onboarded from `us-east-1`**.
  Launched elsewhere, the role is still created but the CUR is skipped; the stack's
  `BillingCurStatus` output reports why. Connections with an existing CUR are unaffected by region.
  The CUR bucket uses `DeletionPolicy: Retain`, so billing data is never deleted on stack removal.

### Audit and CloudTrail-owner connection types removed
* The deprecated **audit** and **cloudtrail-owner** features are gone: their templates, the
  discovery Lambda's CloudTrail/audit detection, and the `cloudtrail:DescribeTrails` permission.
* The reactor payload contract is **unchanged** — `links.audit`, `links.cloudtrail_owner`, and the
  `discovery.*cloudtrail*` / `is_audit_account` / `is_cloudtrail_owner_account` fields remain and
  are emitted as `null` / `false`.

## New Features

### Single nested stack (was 6)
* `connected_account.yaml` **inlines** the Discovery and Notification Lambdas (native
  `AWS::Lambda::Function` + `AWS::IAM::Role`) and provisions resources through one nested
  `ConnectionResources` stack (`services/account_type/account_resources.yaml`, merging the former
  resource_owner + master_payer templates). The notification Lambda no longer scrapes sibling
  stack outputs; it receives values as direct properties and drops `AWSCloudFormationReadOnlyAccess`.

### Shared access policy (DRY)
* The connection role's 19 read-only statements live once in a single `CommonAccessManagedPolicy`
  (`AWS::IAM::ManagedPolicy`); the billing CUR-bucket statement is layered inline only for billing
  connections.

### Migration: re-adopt existing CUR + guided cleanup
* Discovery re-adopts an account's existing CloudZero CUR (no duplicate CUR), so moving from an
  older CloudZero stack is seamless. Discovery also detects previously-deployed CloudZero stacks
  (via `cloudformation:DescribeStacks`) and surfaces them in the `DetectedLegacyConnectionStacks`
  stack output. When a billing connection has a CUR bucket and a legacy stack is detected, a
  `CLOUDZERO_CLEANUP_GUIDE.md` is written to the **root of the connected CUR bucket** with the safe
  deletion steps (a `Custom::CleanupGuide` resource backed by `src/cleanup_guide.py`).

### `Stage` parameter
* Both parent templates carry a `Stage` parameter (`prod` / `dev`) selecting the
  `CallbackConfiguration` mapping, so the two files differ only by the `Stage` default.

### Code clarity & equal CloudZero principals
* The discovery and notification handlers were rewritten into straightforward procedural flows.
* The reactor and connections accounts are presented as co-equal trust principals on the role.

## Deployment Notes

* Launch (or update) the stack with **`CAPABILITY_NAMED_IAM`**. The new `cloudzero-connection`
  role name does not collide with the old CFN-generated role names, so the new stack deploys
  cleanly alongside an older one; delete the old stack afterward (see `DetectedLegacyConnectionStacks`
  and the cleanup guide in the CUR bucket). Validate on a fresh deploy in a test account, including
  the billing-connection (existing-CUR and new-CUR) paths.
* **Follow-up:** `policies/` and `terraform/` still carry the old terminology / audit / cloudtrail
  definitions to reconcile in a separate change.
