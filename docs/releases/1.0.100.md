# [1.0.100](https://github.com/Cloudzero/provision-account/compare/1.0.99...1.0.100) (2026-06-09)

> Add `connectors_account_id` / `ConnectorsAccountId` so the dedicated CloudZero connections account can assume the cross-account role

## Features

### Connections-account trust principal on the CloudZero role
A new optional parameter adds the dedicated CloudZero connections account (`559846027439`) as a trust principal on every CloudZero-provisioned IAM role, matching the existing reactor principal one-for-one. Backward compatible: existing customers re-deploying with no parameter changes pick up the default automatically; no impact on existing functionality.

This re-introduces the second trust principal that was added in 1.0.98 and reverted in 1.0.99, now pointing at the dedicated connections account rather than the prior value.

- **Terraform** (`cloudzero-aws`): new `connectors_account_id` variable. Default `559846027439`.
- **Terraform** (`cloudzero-payer`, `cloudzero-resource`): new `connectors_account_id` local (matches the existing `cz_account_id` pattern in these modules). Default `559846027439`.
- **CloudFormation** account-type templates (`master_payer.yaml`, `resource_owner.yaml`): new `ConnectorsAccountId` parameter. Default `559846027439`.
- **CloudFormation** parent templates (`connected_account.yaml`, `connected_account_dev.yaml`): `ConnectorsAccountId` added to the `CallbackConfiguration` mapping and passed through to the resource-owner and master-payer nested stacks. The dev parent uses the dev connections account (`483772923246`).

The deprecated `audit.yaml` and `cloudtrail_owner.yaml` account-type templates are intentionally unchanged.

Override only if directed by CloudZero support.
