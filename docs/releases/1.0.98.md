# [1.0.98](https://github.com/Cloudzero/provision-account/compare/1.0.97...1.0.98) (2026-05-26)

> Add `connectors_account_id` / `ConnectorsAccountId` to allow a second CloudZero AWS account to assume the cross-account role

## Features

### Second trust principal on the CloudZero role
A new optional parameter adds a second CloudZero AWS account as a trust principal on every CloudZero-provisioned IAM role (and the CloudTrail-owner SQS queue policy), matching the existing reactor principal one-for-one. Backward compatible: existing customers re-deploying with no parameter changes pick up the default automatically; no impact on existing functionality.

- **Terraform** (`cloudzero-aws`): new `connectors_account_id` variable. Default `931830253929`.
- **Terraform** (`cloudzero-payer`, `cloudzero-resource`): new `connectors_account_id` local (matches the existing `cz_account_id` pattern in these modules). Default `931830253929`.
- **CloudFormation** account-type templates (`master_payer.yaml`, `audit.yaml`, `resource_owner.yaml`, `cloudtrail_owner.yaml`): new `ConnectorsAccountId` parameter. Default `931830253929`.
- **CloudFormation** parent templates (`connected_account.yaml`, `connected_account_dev.yaml`): `ConnectorsAccountId` added to the `CallbackConfiguration` mapping and passed through to each nested account-type stack.

Override only if directed by CloudZero support.
