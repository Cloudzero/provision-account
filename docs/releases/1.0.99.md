# [1.0.99](https://github.com/Cloudzero/provision-account/compare/1.0.98...1.0.99) (2026-06-08)

> Revert the second CloudZero trust principal (`ConnectorsAccountId` / `connectors_account_id`) added in 1.0.98

## Reverts

### Removed second trust principal on the CloudZero role
Reverts the change from 1.0.98 (CP-42080, #107) that added a second CloudZero AWS account (`931830253929` prod / `618300337335` dev) as a trust principal on every CloudZero-provisioned IAM role and the CloudTrail-owner SQS queue policy. Each `Principal.AWS` collapses back to the single reactor principal; the `ConnectorsAccountId` parameters, `connectors_account_id` variable/locals, and `CallbackConfiguration` mapping entries are removed. The existing reactor principal (`061190967865` prod / `998146006915` dev) is unchanged.

## Deployment Notes

* Code revert only. Already-deployed customer stacks retain the second trust principal until they re-deploy (CloudFormation `update-stack`) or re-apply Terraform against this release.
* The existing reactor principal is preserved, so current functionality is unaffected.
